# 情報セキュリティ・プライバシー基本方針 (Information Security Policy)

本ドキュメントは、ポートフォリオサイト、クライアントWebサイト、および各種Webプロダクトの構築・公開・管理における情報セキュリティおよびプライバシー保護の基本方針を定めたものである。

---

## 1. 個人情報 (PII) の保護と露出防止

Webサイトはインターネット上に広く公開される可能性があるため、個人情報（Personally Identifiable Information）の取り扱いには細心の注意を払うこと。

1. **電話番号・詳細な住所の非公開**:
   - ソースコードおよび公開コンテンツ上に、個人の電話番号や詳細な居住地・住所を記載しないこと。掲載する場合は「東京都 (Tokyo, Japan)」等の広域地域表現にとどめること。
2. **連絡先メールアドレスの難読化と運用**:
   - 個人のプライベートアドレス（個人のメインGmail等）を直接公開せず、専用の問い合わせフォームまたは公開用パブリックアドレス（例: `contact@example.com`）を使用すること。
   - HTML内に `mailto:` 形式でメールアドレスを直書きするとスパムクローラーの標的となるため、難読化またはフォーム形式を採用すること。

---

## 2. 秘密保持契約 (NDA) と制作実績の掲載基準

クライアント案件や共同開発プロジェクトを実績（Works / Portfolio）として公開・掲載する場合は、以下の基準を厳守すること。

1. **NDA（秘密保持契約）の遵守**:
   - 事前にクライアントや関係者の明確な書面許可（またはメール承認）が得られていないプロジェクトは、ポートフォリオに一切掲載してはならない。
2. **抽象化・デモ化の適用**:
   - 公開許可が得られない場合は、「大手メーカー向けECサイトリニューアル（実績概要）」のように企業名や固有デザインを特定できない形に抽象化するか、自作の架空デモプロジェクトを作成して代替すること。
3. **商標・ロゴ使用の事前確認**:
   - クライアントやサードパーティの企業ロゴ・商標画像を無断で使用してはならない。

---

## 3. パブリックリポジトリ公開対策

コードを GitHub 等のパブリックリポジトリに公開する際の情報漏洩防止方針。

1. **公開前の情報スクリーニング**:
   - ソースコード、コミットコメント、コメントアウトされた行に、内部URL、開発用パスワード、テスト用個人情報が含まれていないか事前に確認すること。
2. **リポジトリ設定の原則**:
   - 開発中および機密情報を含む可能性のあるプロジェクトはデフォルトで「Private リポジトリ」として管理し、安全性が確認された後にのみ Public 化を行うこと。
