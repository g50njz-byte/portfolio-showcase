# Git 運用セキュリティガイド

GitおよびGitHubを使用してWebサイト・プロダクトのソースコードを管理・公開する際、誤って機密情報や不要なファイルをネット上に公開しないための手順です。

---

## 1. `.gitignore` の設定と役割

`.gitignore` ファイルは、Gitの管理（追跡）対象から除外したいファイルやフォルダを指定するための設定ファイルです。

### 主要な除外対象
* **OSが自動生成するファイル**: `.DS_Store` (Mac), `Thumbs.db` (Windows)
* **開発環境・サーバーの一時ファイル**: `.log`, `node_modules/`, `.cache/`
* **機密設定ファイル**: `.env`, `.env.local` (APIキーやパスワード等の環境変数)

### プロジェクトでの `.gitignore` 設置場所
各プロジェクトのルートディレクトリに配置し、環境変数や一時ファイルがリポジトリに含められないように管理します。

---

## 2. 万が一、機密情報をコミット・プッシュしてしまった場合の対処法

パスワードやAPIキーなどの機密情報を誤って GitHub（パブリックリポジトリ）にプッシュしてしまった場合、単に「ファイルを修正して再度コミットする」だけでは**不十分**です。Gitの履歴に残っているため、悪意あるボット等に過去の履歴からキーを復元される危険性があります。

### 推奨される対処手順
1. **キー・認証情報の無効化 (最優先・即座に実行)**:
   - 漏洩したAPIキー、トークン、パスワードを該当サービスの管理画面で即座に再生成（リロテート）または削除し、古いキーが無効な状態にしてください。
2. **履歴の書き換え (Git上の履歴から完全に消去)**:
   - Gitリポジトリの全履歴から該当シークレットを消去するには、以下のツールを使用します：
     - **git-filter-repo** (公式推奨の履歴削除ツール)
     - **BFG Repo-Cleaner**
   - 履歴削除後は `git push origin --force --all` で強制上書きを行います。

---

## 3. SSHキー・トークン認証による安全な接続

GitHubとの通信には、ユーザー名とパスワードの直接入力ではなく、**SSHキー** または **パーソナルアクセストークン (PAT)** を使用してください。
